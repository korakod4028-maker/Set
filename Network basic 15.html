01 / OVERVIEW

Transport Layer คืออะไร

ชั้นที่ 4 ของ OSI (อยู่ใน Transport Layer ของ TCP/IP) ทำหน้าที่ส่งข้อมูลระหว่าง แอปพลิเคชัน ต้นทาง–ปลายทาง ไม่ใช่แค่ระหว่างเครื่อง

  • Segmentation / Reassembly — แบ่งข้อมูลก่อนส่ง ประกอบกลับที่ปลายทาง
  • Multiplexing — หลายแอปใช้เครือข่ายพร้อมกัน แยกด้วย Port
  • Reliability & Flow Control — เฉพาะ TCP
TCP/IP Layerตัวอย่างPDU
ApplicationHTTP, DNS, SSH, SMTPData
TransportTCP, UDPSegment (TCP) / Datagram (UDP)

จำIP = ไปเครื่องไหน · Port = ไปแอปไหน · Transport Layer = ดูแลการคุยระหว่างแอป
02 / TCP vs UDP

เปรียบเทียบ TCP และ UDP

TCP — Reliable

เหมือนพัสดุมีระบบติดตาม: Handshake, ACK, Sequence Number, Retransmission, Flow & Congestion Control

UDP — Low Latency

เหมือนประกาศผ่านลำโพง: ส่งเลย ไม่รอยืนยัน ไม่ส่งซ้ำให้ ภาระน้อย

หัวข้อTCPUDP
รูปแบบConnection-orientedConnectionless
ความน่าเชื่อถือมี (ACK + Retransmit)ไม่รับประกัน
ลำดับข้อมูลSequence Numberไม่มี (แอปจัดการเอง)
Flow / Congestion Controlมี (Window)ไม่มี
Headerขั้นต่ำ 20 B8 B คงที่
ใช้กับHTTP/1.1-2, HTTPS, SSH, FTP, SMTP, DBDNS, DHCP, VoIP, สตรีม, เกม, TFTP, SNMP, QUIC/HTTP3

Header ที่ควรรู้

  • UDP (4 ฟิลด์ × 2 B = 8 B): Source Port, Destination Port, Length, Checksum
  • TCP: Src/Dst Port, Seq, Ack Number, Flags (SYN, ACK, FIN, RST, PSH, URG), Window Size, Checksum

Window = Flow Control + Congestion Control

Flow Control: ผู้รับบอกผ่าน Window Size ว่ารับได้เท่าไร · Congestion Control: ผู้ส่งลดอัตราเมื่อเครือข่ายแออัด (Slow Start, Congestion Window)

ข้อสอบชอบหลอกWindow Size ไม่ได้ทำ Segmentation — มันคุมปริมาณข้อมูลที่ส่งได้ก่อนรอ ACK
03 / HANDSHAKE

TCP Three-Way Handshake & Teardown

กดปุ่มเพื่อดูทีละขั้น (ตัวเลข Seq เป็นตัวอย่าง)

Client
10.1.1.10
Server
10.1.1.254:80
เริ่มต้น: Client ยังไม่ได้ติดต่อ Server

ปิดการเชื่อมต่อ

ปกติใช้ FIN → ACK → FIN → ACK (4 ขั้น) ส่วน RST คือตัดทันที เช่น เชื่อมไปพอร์ตที่ไม่เปิด จะได้ RST กลับมา = Connection refused ต่างจากโดน Firewall DROP ที่เงียบจน timeout

Socket = IP + Port

Client  10.1.1.10:1099  ──►  10.1.1.254:80  Server
Socket Pair = (Src IP, Src Port, Dst IP, Dst Port, Protocol)

Source Port คือ "ที่อยู่ตอบกลับ" ทำให้เครื่องเดียวเปิดหลายการเชื่อมต่อไปเซิร์ฟเวอร์เดียวกันได้ ใน Linux/OS จริงมักใช้ช่วง ephemeral เช่น 32768–60999 (Linux) ไม่ใช่ 1099 เสมอไป

รู้ไว้DNS ใช้ 53 ทั้ง UDP (query ทั่วไป) และ TCP (zone transfer, response ใหญ่) · DHCP: Server 67, Client 68 (UDP)
05 / TOOLS

เครื่องมือตรวจ Connection

:: Windows
netstat -ano          # ทุก connection เป็นตัวเลข + PID
netstat -n            # IP/Port เป็นตัวเลข
tasklist | findstr 1234

# Linux (ใช้ ss แทน netstat ที่เลิกพัฒนา)
ss -tuln              # TCP/UDP ที่ LISTEN เป็นตัวเลข
ss -tnp               # connection + process
nc -vz host 443       # ทดสอบว่า port เปิดไหม
curl -v https://host  # ดู TCP/TLS/HTTP
sudo tcpdump -i any port 53
Stateความหมาย
LISTENING / LISTENรอรับการเชื่อมต่อ
ESTABLISHEDเชื่อมต่อแล้ว
SYN_SENTส่ง SYN แล้ว รอ SYN-ACK (ค้างนาน = ถูก block/ปลายทางไม่ตอบ)
TIME_WAITรอก่อนปิดสมบูรณ์
CLOSE_WAITอีกฝั่งปิดแล้ว แอปเรายังไม่ปิด (เยอะมาก = bug แอปไม่ close socket)
06 / CLOUD ENGINEER

นำไปใช้ในงานจริง

Security Group / NACL / Firewall

กฎอ้างอิง Protocol + Port เช่น เปิด TCP 443 เข้า, TCP 22 เฉพาะ IP แอดมิน ห้ามเปิด 0.0.0.0/0 ที่ 22/3389

Load Balancer L4 vs L7

L4 (NLB) ตัดสินจาก IP+Port (TCP/UDP) เร็ว · L7 (ALB) อ่าน HTTP path/header

Health Check

TCP check = พอร์ตเปิดไหม · HTTP check = ตอบ 200 ไหม แอปค้างแต่พอร์ตเปิด TCP check ยังผ่าน

NAT & Ephemeral Ports

NAT Gateway แมปหลายเครื่องผ่าน IP เดียวด้วย Port ถ้าหมด = port exhaustion เชื่อมต่อออกไม่ได้

DNS & Latency

DNS ใช้ UDP 53 ถ้า SG/NACL ปิด UDP 53 ระบบจะ "เน็ตไม่ได้" ทั้งที่ ping IP ได้

QUIC / HTTP/3

วิ่งบน UDP 443 ถ้าเปิดแค่ TCP 443 ผู้ใช้จะ fallback เป็น HTTP/2

Troubleshooting Flow

1 DNS resolve ได้ไหม?      dig / nslookup
2 Route ถึงไหม?            ping / traceroute
3 Port เปิดไหม?            nc -vz host port
4 Firewall/SG ผ่านไหม?     timeout = DROP · refused = ไม่มี service
5 แอปตอบถูกไหม?            curl -v / logs
07 / CORRECTIONS

ข้อมูลที่แก้ไข / เพิ่มจากเอกสารต้นฉบับ

แก้Cisco เขียน "Transport Control Protocol" ชื่อที่ถูกคือ Transmission Control Protocol
แก้เอกสารระบุ Well-Known = 1–1023 บางที่และ 0–1023 บางที่ ช่วงทางการคือ 0–1023 (พอร์ต 0 สงวนไว้)
Typo โจทย์"TFP" = TFTP (UDP 69) และ "UP" = UDP
แก้"TCP Window ขึ้นกับความน่าเชื่อถือเครือข่าย" ไม่ครบ: Window Size คือ Flow Control (ฝั่งรับ) ส่วน Congestion Window คือฝั่งส่ง
แก้"UDP ไม่มี Flow Control" ถูก แต่เอกสารบางจุดว่า "ไม่มี Sequence Number" — แอป (เช่น RTP, QUIC) ใส่ลำดับเองได้
