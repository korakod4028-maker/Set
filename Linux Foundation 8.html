📊 top คืออะไร
top แสดงสถานะการทำงานของระบบแบบ Real-time อัปเดตหน้าจอต่อเนื่อง (Default ทุก 3 วินาที) เป็นเครื่องมือหลักของงาน SysAdmin / Cloud Engineer ในการตรวจ CPU, RAM และโพรเซสที่กินทรัพยากร

โครงสร้างหน้าจอ top แบ่งเป็น 2 ส่วน: ส่วนหัว (Header) 5 บรรทัดแรก แสดงภาพรวมระบบ และ ตารางโพรเซส (Process List) ด้านล่าง แสดงรายละเอียดทีละโพรเซส

บรรทัดที่ 1 — System Overview
🕐 เวลา, Uptime, Users, Load Average
top - 19:38:28 up 2 days, 20:47, 0 users, load average: 0.52, 0.58, 0.59
19:38:28เวลาปัจจุบันของระบบ
up 2 days...Uptime — เปิดเครื่องมานานเท่าไหร่แล้วนับจาก boot ล่าสุด
0 usersจำนวนผู้ใช้ที่ล็อกอินอยู่ในระบบขณะนั้น เช็กละเอียดเพิ่มได้ด้วย who หรือ w
load averageค่าเฉลี่ยภาระงานของ CPU ในช่วง 1, 5 และ 15 นาทีที่ผ่านมา (เรียงจากซ้ายไปขวา)

⚠️ ข้อควรระวัง — Load ต้องอ่านคู่กับจำนวน CPU Core เสมอ: ค่า Load เดียวกันมีความหมายต่างกันตามจำนวน Core บนเครื่อง

💡 เช็กจำนวน CPU Core ด้วยคำสั่ง nproc แล้วเอา Load Average หารด้วยจำนวน Core เพื่อดู % การใช้งานจริง — เป็นเทคนิคที่ Cloud Engineer ใช้ประเมิน Server ทุกวัน

บรรทัดที่ 2 — Tasks (สถานะโพรเซส)
⚙️ Tasks: total, running, sleeping, stopped, zombie
Tasks: 6 total, 1 running, 5 sleeping, 0 stopped, 0 zombie
totalโพรเซสทั้งหมดที่บันทึกไว้ในตารางโพรเซสขณะนั้น
runningโพรเซสที่กำลังประมวลผลอยู่บน CPU ณ ตอนนั้นจริงๆ
sleepingโพรเซสที่หยุดรอทรัพยากรหรือรอการรับส่งข้อมูล (I/O) อยู่ — สถานะปกติของโพรเซสส่วนใหญ่ในระบบ
stoppedโพรเซสที่ถูกสั่งหยุดทำงานชั่วคราว เช่น กด Ctrl + Z
zombieโพรเซสที่ทำงานเสร็จแล้วแต่ยังมีชื่อค้างอยู่ในตารางโพรเซส (รอ Parent เรียก wait()/exit()) มักเกิดจากโพรเซสแม่ (Parent) มีปัญหา บางครั้งแก้ได้ด้วยการปิดโพรเซสแม่
บรรทัดที่ 3 — %Cpu(s)
🧮 เปอร์เซ็นต์การใช้งาน CPU
%Cpu(s): 13.9 us, 9.5 sy, 0.0 ni, 76.3 id, 0.0 wa, 0.4 hi, 0.0 si, 0.0 st
ตัวย่อชื่อเต็มความหมาย
usUserCPU ที่ถูกใช้โดยโปรแกรมฝั่งผู้ใช้งาน (user-space)
sySystemCPU ที่ถูกใช้โดยระบบ / Kernel
niNiceCPU ที่ถูกใช้โดยโพรเซสที่ปรับค่า Priority (Niceness > 0 คือยอมทำงานตอนระบบว่าง)
idIdleเวลาที่ CPU ว่างงาน ไม่มีอะไรให้ประมวลผล
waI/O Waitเวลาที่ CPU รอการอ่าน/เขียนข้อมูลจากฮาร์ดแวร์ — ถ้าสูง คอขวดมักอยู่ที่ Disk I/O ไม่ใช่ CPU
hiHardware IRQสัญญาณขัดจังหวะจากอุปกรณ์ฮาร์ดแวร์ จัดการโดย CPU โดยตรง
siSoftware IRQสัญญาณขัดจังหวะจากซอฟต์แวร์ จัดการโดย Kernel
stSteal Timeเวลาที่ VM ต้องรอทรัพยากรจาก Hypervisor — สำคัญมากเวลารันบน Cloud/VM ถ้าค่านี้สูง แปลว่า Host แชร์ทรัพยากรไม่พอ

💡 บน Cloud Instance (AWS/GCP/Azure) ให้จับตา st (Steal Time) เป็นพิเศษ — ถ้าสูงต่อเนื่อง อาจต้อง Upgrade Instance Type หรือย้าย Host

บรรทัดที่ 4-5 — Memory (RAM & Swap)
💾 หน่วยความจำ
MiB Mem : 16217.5 total, 6184.9 free, 9808.7 used, 224.0 buff/cache MiB Swap: 49152.0 total, 48436.2 free, 715.8 used. 6278.3 avail Mem
total / free / usedปริมาณ RAM หรือ Swap ทั้งหมด / ที่ว่างอยู่ / ที่ถูกใช้ไปแล้ว
buff/cacheหน่วยความจำที่ Kernel ดึงไปทำ Buffer และ Page Cache เพื่อเร่งความเร็วการทำงาน — ไม่ใช่หน่วยความจำที่เสียเปล่า สามารถคืนให้โปรแกรมอื่นได้ทันทีเมื่อจำเป็น
avail Memปริมาณ RAM จริงที่เหลืออยู่และพร้อมให้โปรแกรมใหม่ดึงไปใช้ได้ทันที — ค่านี้แม่นยำกว่า free เพราะรวมส่วนที่ reclaim จาก buff/cache ได้แล้ว

⚠️ กับดักข้อสอบ: อย่าตีความว่าเครื่องขาด RAM แค่เพราะ free ตัวเลขต่ำ — ต้องดู avail Mem เป็นหลัก เพราะ Linux จงใจดึง RAM ว่างไปทำ cache เพื่อประสิทธิภาพ

ตารางโพรเซส (Process List)
📑 ความหมายของคอลัมน์
คอลัมน์ชื่อเต็มความหมาย
PIDProcess IDหมายเลขประจำตัวของโพรเซส
USEROwnerผู้ใช้ที่เป็นเจ้าของโพรเซสนั้น
PRPriorityลำดับความสำคัญของโพรเซสที่จัดโดย Kernel (Default Priority)
NINiceค่า Nice ปรับความสำคัญได้ตั้งแต่ 19 (ต่ำสุด) ถึง -20 (สูงสุด) ค่ามาตรฐานคือ 0
VIRTVirtual Memoryหน่วยความจำเสมือนทั้งหมดที่โพรเซสเรียกใช้ (รวมส่วนที่ยังไม่ถูกใช้จริง)
RESResident Memoryหน่วยความจำ RAM จริงที่โพรเซสกำลังใช้อยู่ ณ ขณะนั้น
SHRShared Memoryหน่วยความจำที่แชร์ร่วมกับโพรเซสอื่น เช่น shared library
SStatusสถานะของโพรเซส: R=Running, S=Sleeping, D=Uninterruptible Sleep, Z=Zombie, T=Stopped
%CPUCPU Usageเปอร์เซ็นต์ CPU ที่โพรเซสนั้นใช้อยู่
%MEMMemory Usageเปอร์เซ็นต์ RAM ที่โพรเซสนั้นใช้อยู่
TIME+CPU Timeเวลารวมทั้งหมดที่โพรเซสใช้ CPU ไปนับตั้งแต่เริ่มทำงาน
COMMANDCommandชื่อคำสั่ง/โปรแกรมที่รันโพรเซสนั้นอยู่

ตาราง Process List เรียงตาม %CPU มากไปน้อย เป็นค่า Default — กด Shift + M เพื่อเรียงตาม RAM แทนได้ทันที

🔍 VIRT vs RES vs SHR — ต่างกันอย่างไร
VIRTพื้นที่ Address Space ทั้งหมดที่โพรเซสขอจองไว้ รวมส่วนที่ยัง swap หรือยังไม่ถูกแตะ — มักเป็นตัวเลขใหญ่ที่สุด และไม่ได้แปลว่ากิน RAM จริงเท่านั้น
RESRAM จริงที่โพรเซสใช้อยู่ ณ ตอนนี้ — ตัวเลขที่ควรดูเป็นหลักเวลาหาโพรเซสกิน RAM
SHRส่วนของ RES ที่ถูกแชร์กับโพรเซสอื่น (เช่น .so library) — ถ้าปิดโพรเซสนี้ RAM ส่วนนี้อาจไม่ถูกคืนทั้งหมดถ้ายังมีโพรเซสอื่นใช้อยู่
การปรับแสดงผลและรูปแบบ

⇧Mเรียงตาม %MEM

🔎 Filtering, Search & Actions
nจำกัดจำนวนโพรเซสที่จะแสดงผล (ใส่ 0 เพื่อแสดงทั้งหมด)
uกรองแสดงเฉพาะโพรเซสของผู้ใช้ที่ระบุ (เช่น พิมพ์ root)
oค้นหาโพรเซส แบบไม่สนตัวพิมพ์เล็ก-ใหญ่ (Case-insensitive)
⇧Oค้นหาโพรเซส แบบสนตัวพิมพ์เล็ก-ใหญ่ (Case-sensitive)
sเปลี่ยนความถี่ในการอัปเดตหน้าจอ (Default คือทุก 3 วินาที)
kสั่งปิดโพรเซส (Kill) — ระบบจะให้กรอกหมายเลข PID แล้วเลือก Signal
rสั่งเปลี่ยนค่า Priority (renice) ของโพรเซส — ระบบจะให้กรอก PID แล้วใส่ค่า Nice ใหม่
⇧Wบันทึกการตั้งค่าทั้งหมดลงไฟล์ .toprc (หรือ ~/.config/procps/toprc) เพื่อใช้ค่านี้ในครั้งถัดไป
qออกจากโปรแกรม top

⚠️ กับดักข้อสอบ: k ใน top สั่ง kill ทันทีหลังกรอก PID/Signal — ต่างจาก kill command ที่พิมพ์ผ่าน shell โดยตรง แต่ผลลัพธ์คือส่ง signal เดียวกัน (default SIGTERM)

🖥️ รันคำสั่ง top ร้วมกับ Options ผ่าน Terminal
topเปิด top แบบมาตรฐาน อัปเดตทุก 3 วินาที
top -o %MEMเปิด top โดยจัดเรียงตาม RAM ทันที
top -o %CPUเปิด top โดยจัดเรียงตาม CPU ทันที (เทียบเท่า Default)
top -cเปิด top โดยแสดง Full Path ของคำสั่งตั้งแต่เริ่ม
top -u rootเปิด top โดยกรองแสดงเฉพาะโพรเซสของ root
top -d 5ตั้งความถี่การอัปเดตหน้าจอทุก 5 วินาที (Default คือ 3)
top -n 1รันแค่ 1 รอบแล้วออกทันที เหมาะสำหรับใช้ใน Script
top -b -n 1Batch mode — แสดงผลแบบ plain text ไม่มี interactive UI ใช้ redirect ลงไฟล์หรือใน cron job ได้
top -p PIDแสดงเฉพาะโพรเซสตามหมายเลข PID ที่ระบุ (ใส่ได้สูงสุด 20 PID คั่นด้วย comma)

💡 Engineer Tips — ใช้งานจริง
→
ใช้ top -o %MEM เป็นคำสั่งแรกเวลาเช็ก Server ที่รายงานว่า RAM เต็ม — เจอตัวการได้ไวกว่าเปิด top เฉยๆ แล้วกด ⇧M เอง
→
คู่มือ htop เป็นทางเลือกที่มี UI สีสันและใช้เมาส์ได้ แต่ top มีติดตั้งมาให้ทุกระบบ Linux เป็นค่าเริ่มต้น — ต้องคล่อง top ก่อนเสมอเพราะไม่ใช่ทุก Server จะมี htop ให้ใช้
→
เจอ st (Steal Time) สูงผิดปกติบน Cloud VM ให้สงสัย Host ถูกแชร์ทรัพยากรเกิน (Noisy Neighbor) — รายงานให้ทีม Infra ตรวจสอบ
→
ใช้ top -b -n 1 | head -20 เพื่อ snapshot สถานะระบบแบบเร็ว เก็บ log ไว้ debug ย้อนหลังหรือแปะใน incident report
→
ถ้า Load Average สูงแต่ %CPU us/sy รวมกันต่ำ ให้สงสัยว่าเป็นปัญหาที่ wa (I/O Wait) ไม่ใช่ CPU ไม่พอ — เช็ก Disk I/O ต่อด้วย iostat
→
โพรเซสสถานะ D (Uninterruptible Sleep) ค้างนานผิดปกติ มักแปลว่ากำลังรอ Disk/Network I/O ที่มีปัญหา — kill -9 มักไม่ได้ผลกับสถานะนี้จนกว่า I/O จะจบ
