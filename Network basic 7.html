MAC ย่อ: H1=AA, H2=BB, H3=CC, H4=DD. ลองส่งซ้ำ ๆ สังเกตว่าเมื่อไหร่ Flood และเมื่อไหร่ส่งตรง

MACPort
    ลองทำตามนี้: (1) H1→H4 = Flood เพราะยังไม่รู้ DD (2) H4→H1 = ส่งตรง เพราะรู้ AA แล้ว และตอนนี้เรียนรู้ DD (3) H1→H4 อีกครั้ง = ส่งตรง ไม่ Flood (4) ส่งไป Broadcast = Flood เสมอ

    เพิ่มเติมที่ต้องรู้ก่อนไปทำงาน

    โครงสร้าง MAC Address (48 bit)

    AA:BB:CC:11:22:33 → 3 ไบต์แรก = OUI (ผู้ผลิต) 3 ไบต์หลัง = ลำดับของ NIC. แบ่ง 3 แบบ: Unicast (1 ต่อ 1) · Multicast (bit ต่ำสุดของไบต์แรก = 1) · Broadcast FF:FF:FF:FF:FF:FF (ทุกเครื่องใน Broadcast domain). Switch ไม่เรียนรู้ Broadcast/Multicast เป็น Source และ Flood Broadcast เสมอ

    ส่วนที่เกี่ยวข้องในงานจริง

    • ARP: เครื่องส่ง Broadcast ถาม “IP นี้ MAC อะไร” แล้วเก็บใน ARP cache. ดูด้วย ip neigh
    • VLAN (802.1Q): แบ่ง Switch ตัวเดียวเป็นหลาย Broadcast domain ด้วย tag 4 B
    • Duplex: Switch สมัยใหม่เป็น Full-duplex จึงไม่ต้องใช้ CSMA/CD (กลไกตรวจ collision ของ Hub/Half-duplex)
    • วิธีส่งต่อ: Store-and-forward (ตรวจ FCS ก่อนส่ง) กับ Cut-through (ส่งทันทีหลังอ่าน Dest MAC)
    • MTU: Payload สูงสุด 1500 B ปกติ. Jumbo frame ถึง ~9000 B ต้องตั้งตลอดเส้นทาง

    โยงกับ Cloud และ Linux

    • VPC ใน AWS ทำงานเหมือน Virtual Switch: instance แต่ละตัวมี ENI ที่มี MAC ของตัวเอง; Broadcast/ARP ถูกจัดการโดยระบบเครือข่ายเสมือน ไม่ได้ Flood แบบ Switch จริง
    • AWS รองรับ Jumbo frame (MTU 9001) ภายใน VPC แต่ผ่าน Internet Gateway ใช้ 1500 ปัญหา MTU ไม่ตรงทำให้ Packet ใหญ่หายแบบงงได้
    • คำสั่งที่ควรรู้: ip link (MAC/MTU) · ip neigh (ARP) · bridge fdb show (MAC table ของ Linux bridge) · tcpdump -e (ดู MAC ใน Frame) · Cisco: show mac address-table

    ข้อที่ตรวจแก้และเติมจากไฟล์ต้นฉบับ

    1. “Ethernet = Layer 2” ถูกสำหรับข้อสอบ แต่ไม่ครบ
    IEEE 802.3 ครอบคลุม Layer 1 (สัญญาณ สาย) และ Layer 2 (MAC, Frame). ตอบข้อสอบว่า Layer 2 Data Link
    2. Flood ไม่เท่ากับ Broadcast
    ในข้อ Q1 ตัวเลือก “broadcasts out of all ports” ผิดเพราะรวมพอร์ตขาเข้า. Flood = ทุกพอร์ต ยกเว้นพอร์ตขาเข้า. ส่วน Broadcast frame คือ Dest = FF:FF:FF:FF:FF:FF ซึ่งก็ถูก Flood เช่นกัน
    3. Hub ไม่ใช่แค่ “ล้าสมัย”
    เป็นอุปกรณ์ Layer 1 ที่ทวนสัญญาณไปทุกพอร์ต ทำให้เกิด Collision domain เดียวและชนกันได้ จึงถูกแทนที่ด้วย Switch
    4. “Frame = ซองจดหมาย” ควรเสริม
    ซอง (MAC) ถูกเปลี่ยนใหม่ทุก hop แต่จดหมายข้างใน (IP Packet) คงเดิมตั้งแต่ต้นทางถึงปลายทาง
    5. NIC ทิ้ง Frame ที่ไม่ใช่ของตัวเอง
    ถูกในโหมดปกติ. ข้อยกเว้น: promiscuous mode (เช่น Wireshark) NIC รับทุก Frame. และ Broadcast/Multicast ที่สนใจจะถูกรับ ไม่ทิ้ง
    6. MAC aging 5 นาที
    เป็นค่า default ของ Cisco และ Linux bridge (300 วินาที) ปรับได้ ไม่ใช่ค่าตายตัว. ถ้าเครื่องย้ายพอร์ต Switch จะอัปเดตรายการเมื่อเห็น Source MAC เดิมจากพอร์ตใหม่
    7. ที่เอกสารไม่ได้ระบุ: ขนาด Preamble 7 B / SFD 1 B / MAC 6 B / Type 2 B / FCS 4 B (CRC-32) และช่วง Payload 46–1500 B
