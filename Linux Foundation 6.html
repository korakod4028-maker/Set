READING(1)User CommandsREADING(1)

01 เช็กไฟล์ก่อนเปิดเสมอ

ก่อนเปิดไฟล์ใด ๆ วิศวกรมืออาชีพจะไม่ "เดา" — ต้องรู้ก่อนว่าไฟล์มีอยู่จริง มีสิทธิ์เข้าถึงหรือไม่ และเป็นไฟล์ประเภทใด เพื่อเลือกเครื่องมือเปิดไฟล์ให้ถูกต้อง

01
ls -l [filename] — ตรวจสอบว่าไฟล์มีอยู่จริง ดูเจ้าของไฟล์ สิทธิ์ (permission) และขนาดไฟล์
ใช้บ่อยตอน debug ปัญหา "permission denied" บนเซิร์ฟเวอร์จริง
02
file [filename] — เช็กประเภทไฟล์ก่อนเปิด เช่น ASCII text, binary, gzip compressed
⚠️ ห้ามใช้ cat เปิดไฟล์ไบนารีโดยตรง เพราะจะพ่นอักขระแปลก ๆ ทำให้ terminal ค้างหรือแสดงผลเพี้ยนได้
READING(1)Core CommandsREADING(1)

02 เครื่องมืออ่านไฟล์หลัก

คำสั่งพื้นฐาน 5 ตัวที่ต้องคล่องแบบไม่ต้องคิด เพราะจะถูกใช้แทบทุกวันในงาน Cloud / DevOps

คำสั่งการทำงานข้อดีข้อจำกัด / วิธีออก
cat พิมพ์เนื้อหาทั้งไฟล์ออกมาทีเดียวย่อจาก concatenate เร็ว เหมาะกับไฟล์เล็ก ไฟล์ใหญ่จะไหลทะลักเต็มจอ อ่านไม่ทัน
more แสดงผลทีละหน้าแบบ interactive อ่านสะดวกกว่า cat สำหรับไฟล์ยาว เลื่อนได้ทิศทางเดียว (ลงอย่างเดียว) — กด Enter เลื่อนบรรทัด, Space เลื่อนหน้า, กด q ออก
less แสดงผลทีละหน้าแบบยืดหยุ่นกว่า more เลื่อน ขึ้น-ลงได้อิสระ + ค้นหาคำได้ด้วย / กด q เพื่อออก
head แสดงส่วนต้นของไฟล์ ดีฟอลต์ 10 บรรทัดแรก, ระบุจำนวนด้วย -n เช่น head -n5 file —
tail แสดงส่วนท้ายของไฟล์ ดีฟอลต์ 10 บรรทัดสุดท้าย, ระบุจำนวนด้วย -n เช่น tail -n2 file —
VIM(1)Text Editor / ViewerVIM(1)

03 vim & view — Text Editor

vim ไม่ใช่แค่ตัวอ่านไฟล์ แต่เป็น text editor ที่ทรงพลังที่สุดตัวหนึ่งบน Linux มี 3 โหมดการทำงานหลักที่ต้องจำให้ขึ้นใจ

COMMAND MODE

โหมดเริ่มต้นเมื่อเปิดโปรแกรม ใช้สั่งงาน เช่น เลื่อนเคอร์เซอร์ ลบบรรทัด บันทึกไฟล์ ค้นหา ฯลฯ

INSERT MODE

โหมดพิมพ์ / แก้ไขข้อความจริง เข้าโหมดนี้ด้วยปุ่ม i, a, หรือ o

VISUAL MODE

โหมดคลุมดำ (select) ข้อความ เพื่อคัดลอก ลบ หรือแก้ไขเป็นกลุ่ม เข้าด้วยปุ่ม v

กด ESC เพื่อกลับสู่ COMMAND Mode ได้เสมอ ไม่ว่าจะอยู่โหมดไหนก็ตาม

🚪 คำสั่งออกจาก vim (พิมพ์ใน COMMAND mode)

  • :q ออกจากโปรแกรม (ใช้ได้เมื่อไม่มีการแก้ไขค้างอยู่)
  • :q! ออกโดย ไม่บันทึก การแก้ไขที่ทำไว้
  • :wq บันทึกแล้วออก (Write & Quit) — หรือใช้ :x ได้ผลเหมือนกัน

👁️ เปิดแบบอ่านอย่างเดียว (Read-Only)

view [filename] = เปิดไฟล์ด้วย vim ในโหมดอ่านอย่างเดียว ป้องกันการเผลอแก้ไขข้อมูลสำคัญโดยไม่ตั้งใจ — เหมาะมากเวลาต้องเปิดไฟล์ config บน production server เพื่อดูเฉย ๆ (ออกด้วย :q)

LESS(1)Search & PipeLESS(1)

04 เทคนิคขั้นสูง: ค้นหา & Pipe

🔎 การค้นหาใน less

พิมพ์ /ข้อความ เพื่อค้นหา (Linux เป็น case-sensitive ตัวพิมพ์เล็ก-ใหญ่ต่างกัน)

กด n → ไปผลลัพธ์ถัดไป (เลื่อนลง)

กด N → ย้อนกลับผลลัพธ์ก่อนหน้า (เลื่อนขึ้น)

🔗 การใช้ Pipe ( | )

เชื่อมคำสั่งต่อกันเพื่อกรองข้อมูล ผลลัพธ์ของคำสั่งซ้ายจะถูกส่งเป็น input ให้คำสั่งขวา

cat testfile | head -n4 | tail -n2

ดึง 4 บรรทัดแรกมาก่อน แล้วตัดเอาเฉพาะ 2 บรรทัดท้ายของกลุ่มนั้น → ได้บรรทัดที่ 3 และ 4 ของไฟล์

BONUS(1)For Cloud EngineersBONUS(1)

05 ภาคเสริม: คำสั่งที่ Cloud Engineer ใช้จริงทุกวัน

เนื้อหาต้นฉบับของ Lesson 6 ยังไม่ครอบคลุมคำสั่งเหล่านี้ แต่จำเป็นมากเมื่อเริ่มทำงานสาย Cloud/DevOps จริง — เพิ่มให้ครบเพื่อเตรียมความพร้อมสัมภาษณ์งานและใช้งานหน้างาน

คำสั่งการทำงานใช้เมื่อไหร่ในงานจริง
tail -f ติดตามไฟล์แบบ real-time โดยไม่ต้องปิดหน้าต่าง ดู log server ที่กำลังเขียนอยู่ เช่น tail -f /var/log/nginx/access.log
grep ค้นหาข้อความ/pattern ในไฟล์ ไล่หา error ใน log จำนวนมาก เช่น grep -i "error" app.log
wc -l นับจำนวนบรรทัดในไฟล์ เช็คขนาด log หรือจำนวน record คร่าว ๆ ก่อนประมวลผล
stat แสดงรายละเอียดไฟล์แบบละเอียดกว่า ls -l (เวลาแก้ไขล่าสุด, inode ฯลฯ) ตรวจสอบว่าไฟล์ถูกแก้ไขล่าสุดเมื่อไหร่ เวลา troubleshoot deployment
> และ >> Redirect output ไปเขียนไฟล์ (> เขียนทับ, >> ต่อท้ายไฟล์) เก็บผลลัพธ์คำสั่งไว้เป็นไฟล์ log เช่น command >> result.log
du -sh ดูขนาดไฟล์/โฟลเดอร์แบบอ่านง่าย (human-readable) เช็คว่า disk เต็มเพราะไฟล์ไหน ก่อน storage เต็มบน server

06 แบบฝึกหัดทบทวน

ลองตอบในใจก่อน แล้วค่อยกดปุ่ม "ดูเฉลย" เพื่อเช็คคำตอบ — ข้อ 1-3 มาจากแบบทดสอบต้นฉบับ ข้อ 4-7 เป็นสถานการณ์จริงที่เพิ่มให้เพื่อเตรียมสัมภาษณ์งาน Cloud Engineer

Q1 / ORIGINAL QUIZ
Which command shows the whole file at once?
1) cat   2) show   3) edit   4) print
cat — พิมพ์เนื้อหาไฟล์ตั้งแต่บรรทัดแรกถึงบรรทัดสุดท้ายออกมาทีเดียวทั้งหมด
Q2 / ORIGINAL QUIZ
This command allows you to navigate (up/down) and search through the file.
1) more   2) edit   3) cat   4) less
less — เลื่อนดูเนื้อหาได้ทั้งขึ้นและลง และค้นหาข้อความได้ด้วยเครื่องหมาย /
Q3 / ORIGINAL QUIZ
I want to see the first 5 lines of the file. Which command is correct?
1) cat file   2) less -N5 file   3) less --head file   4) head -n5 file
head -n5 file — head ใช้ดูส่วนต้นของไฟล์ อาร์กิวเมนต์ -n5 ระบุจำนวน 5 บรรทัดแรก (ตัวเลือกอื่นใช้ syntax ที่ไม่มีอยู่จริง)
Q4 / SCENARIO
คุณ SSH เข้าเซิร์ฟเวอร์ production แล้วต้องการดู log ที่กำลังถูกเขียนแบบ real-time ระหว่างที่ระบบทำงานอยู่ ควรใช้คำสั่งอะไร?
tail -f filename.log — ติดตามไฟล์แบบต่อเนื่อง ไม่ต้องรันคำสั่งซ้ำเมื่อมีบรรทัดใหม่เข้ามา
Q5 / SCENARIO
มีไฟล์ log ขนาด 2GB คุณต้องการหาว่ามีคำว่า "timeout" อยู่กี่ครั้งและตรงไหนบ้าง โดยไม่เปิดไฟล์ทั้งหมด ควรทำอย่างไร?
grep "timeout" filename.log — ค้นหาเฉพาะบรรทัดที่มีคำนั้น เร็วกว่าและประหยัดกว่าการเปิดทั้งไฟล์มาก
Q6 / SCENARIO
ก่อนจะรัน cat เปิดไฟล์ที่ไม่รู้จัก คุณควรตรวจสอบอะไรก่อนเพื่อป้องกัน terminal พัง?
file filename — เช็คประเภทไฟล์ก่อนเสมอ ถ้าเป็นไฟล์ binary ห้ามใช้ cat เปิดตรง ๆ
Q7 / SCENARIO
คุณต้องการดูเฉพาะบรรทัดที่ 8-10 ของไฟล์ config โดยใช้เทคนิค pipe จะเขียนคำสั่งอย่างไร?
cat config | head -n10 | tail -n3 — ดึง 10 บรรทัดแรกมาก่อน แล้วตัดเอา 3 บรรทัดสุดท้ายของกลุ่มนั้น = บรรทัดที่ 8, 9, 10
