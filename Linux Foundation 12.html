การจัดการประวัติคำสั่ง (History)

สรุปเข้มฉบับเตรียมสอบ/เตรียมงานสาย Cloud Engineer — ครอบคลุมการเรียกคำสั่งเก่า การตั้งค่าใน .bashrc ตัวแปรระบบ และแนวปฏิบัติด้านความปลอดภัยที่มักถูกถามในงานจริง

การเรียกใช้คำสั่งเก่า

recall & navigate

คำสั่งที่พิมพ์ไปแล้วจะถูกเก็บไว้ในหน่วยความจำของ shell แบบเรียงลำดับ เราสามารถเรียกกลับมาใช้ซ้ำได้หลายวิธี โดยไม่ต้องพิมพ์ใหม่ทั้งหมด

วิธีการผลลัพธ์
↑ / ↓เลื่อนดูคำสั่งก่อนหน้า/ถัดไปทีละคำสั่ง
historyแสดงรายการคำสั่งทั้งหมด พร้อมเลขลำดับ
history 3แสดงเฉพาะ 3 คำสั่งล่าสุด
history | grep catค้นหาคำสั่งที่เคยพิมพ์ ที่มีคำว่า "cat"
!numberรันคำสั่งตามเลขลำดับทันที เช่น !6
$ history 5
101 cd /var/log 102 ls -la 103 sudo systemctl status nginx 104 tail -f access.log 105 history 5
$ !103 # รันคำสั่งลำดับ 103 ซ้ำ

ทางลัดที่มักถูกมองข้าม (เพิ่มเติม) เพิ่ม

  • !! — รันคำสั่งก่อนหน้าล่าสุดซ้ำ (ใช้บ่อยมากกับ sudo !! เมื่อลืมพิมพ์ sudo)
  • !$ — ดึง argument ตัวสุดท้ายของคำสั่งก่อนหน้ามาใช้ เช่น mkdir test && cd !$
  • !^ — ดึง argument ตัวแรกของคำสั่งก่อนหน้า
  • !ls — รันคำสั่งล่าสุดที่ขึ้นต้นด้วยคำว่า "ls"
  • !ls:p — แสดงคำสั่งที่จะรัน โดยยังไม่รันจริง (print only) ใช้เช็กก่อนยิงคำสั่งอันตราย

ค้นหาแบบโต้ตอบด้วย Ctrl + r

reverse-i-search
  • กด Ctrl+r แล้วพิมพ์คำค้นหา ระบบจะดึงคำสั่งล่าสุดที่ตรงกันขึ้นมาแสดง
  • กด Ctrl+r ซ้ำ เพื่อย้อนหาคำสั่งก่อนหน้าที่ตรงกันมากขึ้น
  • กด Enter เพื่อรันคำสั่งที่เจอ
  • กด Esc เพื่อยกเลิกการค้นหาแต่ยังคงข้อความไว้ที่ prompt
  • เพิ่ม กด Ctrl+g เพื่อยกเลิกทันทีและล้าง prompt กลับเป็นค่าว่าง

การตั้งค่าระบบใน ~/.bashrc

configuration

ตัวแปร shell ต่อไปนี้ควบคุมพฤติกรรมของ history โดยส่วนใหญ่นิยมตั้งค่าไว้ใน ~/.bashrc เพื่อให้มีผลทุกครั้งที่เปิด terminal ใหม่

ตัวแปร / คำสั่งหน้าที่ / ผลลัพธ์
HISTCONTROL=
ignoredups:ignorespace		ไม่บันทึกคำสั่งที่พิมพ์ซ้ำติดกัน และคำสั่งที่ขึ้นต้นด้วยช่องว่าง
shopt -s histappendบันทึกประวัติแบบต่อท้ายไฟล์เสมอ ไม่เขียนทับไฟล์เดิมเมื่อเปิดหลาย terminal พร้อมกัน
HISTSIZE=1000จำนวนคำสั่งสูงสุดที่เก็บใน RAM ระหว่าง session
HISTFILESIZE=2000จำนวนคำสั่งสูงสุดที่เก็บลงไฟล์บนดิสก์
HISTCONTROL=ignoreboth เพิ่มรวมพฤติกรรมของ ignoredups และ ignorespace ไว้ในค่าเดียว (คำสั่งย่อที่ใช้แทนกันได้)
HISTCONTROL=erasedups เพิ่มลบคำสั่งที่ซ้ำกันทุกจุดในประวัติ ไม่ใช่แค่ที่ติดกัน ทำให้ history สะอาดขึ้น
HISTIGNORE="ls:cd:pwd:exit" เพิ่มระบุ pattern คำสั่งที่ไม่ต้องการให้บันทึกเลย เหมาะกับคำสั่งที่ใช้บ่อยแต่ไม่มีค่าให้ค้นย้อนหลัง
HISTTIMEFORMAT="%F %T " เพิ่มแสดงวันที่-เวลาที่รันคำสั่งไว้หน้าแต่ละบรรทัดเมื่อพิมพ์ history — สำคัญมากสำหรับงาน audit log
$ history # หลังตั้ง HISTTIMEFORMAT
201 2026-09-01 14:02:11 sudo apt update 202 2026-09-01 14:03:47 kubectl get pods -A
หมายเหตุ

ต้องแก้ไขไฟล์แล้วรัน source ~/.bashrc หรือเปิด terminal ใหม่ ค่าที่ตั้งจึงจะมีผล

การจัดการไฟล์และตัวแปร

files & variables
  • ตำแหน่งไฟล์: ปกติเก็บที่ ~/.bash_history ระบบจะเขียนลงไฟล์เมื่อปิด session terminal
  • บันทึกลงไฟล์ทันที: history -a — dump ประวัติในเซสชันปัจจุบันลงไฟล์ทันทีโดยไม่ต้องรอปิด terminal
  • เช็กค่าตัวแปร: echo $HISTSIZE (ต้องมี $ นำหน้าเสมอเพื่ออ่านค่า) หรือ set | grep HIST เพื่อดูตัวแปรที่เกี่ยวกับ history ทั้งหมด
  • เปลี่ยนไฟล์เก็บประวัติชั่วคราว: HISTFILE="/path/to/file" มีผลเฉพาะ session ปัจจุบัน
  • เพิ่ม โหลดประวัติจากไฟล์กลับเข้า session: history -r — อ่านไฟล์ history กลับเข้า memory โดยไม่ต้องเปิด terminal ใหม่
  • เพิ่ม คำสั่ง fc: fc -l แสดงประวัติคล้าย history, fc -e vim 105 เปิดคำสั่งลำดับ 105 ด้วย vim เพื่อแก้ไขก่อนรันซ้ำ — มีมาตั้งแต่ POSIX shell ยุคแรก
$ echo $HISTSIZE
1000
$ set | grep HIST
HISTCONTROL=ignoreboth HISTFILE=/home/user/.bash_history HISTFILESIZE=2000 HISTSIZE=1000

การล้างประวัติและการปิดใช้งาน

clear & disable
คำสั่งผลลัพธ์
history -cล้างประวัติใน RAM เท่านั้น — ไฟล์ .bash_history ยังคงอยู่จนกว่าจะปิด session
> ~/.bash_historyส่งความว่างเปล่าไปทับข้อมูลในไฟล์ ทำให้ไฟล์ว่างเปล่าทันที
set +o historyปิดการบันทึกประวัติชั่วคราวสำหรับ session ปัจจุบัน
set -o history เพิ่มเปิดกลับมาบันทึกประวัติอีกครั้งหลังจากสั่งปิดไว้
  • ปิดถาวรเฉพาะผู้ใช้ปัจจุบัน: เพิ่ม set +o history ลงใน ~/.bashrc
  • ปิดถาวรทุกผู้ใช้ในระบบ: เพิ่มลงใน /etc/profile
ข้อควรระวังสำหรับสาย Cloud/DevOps

history -c ล้างได้แค่ในหน่วยความจำ ถ้าลืมและปิด terminal ปกติ ระบบจะยัง flush คำสั่งที่รันไปก่อนหน้าลงไฟล์อยู่ดี หากต้องการปิดการบันทึกจริง ๆ ระหว่างพิมพ์คำสั่งที่มีความลับ (เช่น password, API key) ให้ตั้ง HISTCONTROL=ignorespace แล้วพิมพ์ช่องว่างนำหน้าคำสั่งนั้น หรือใช้ export HISTFILE=/dev/null ก่อนเริ่มงานที่มีความอ่อนไหว

อย่าใช้ history เป็นมาตรการความปลอดภัย

คำสั่งที่รันด้วย sudo, การเข้าถึง secret, หรือ credential ต่าง ๆ ควรใช้ secret manager หรือ environment variable แทนการพิมพ์ตรง ๆ ใน shell เสมอ เพราะ history ถูกออกแบบมาเพื่อความสะดวก ไม่ใช่เพื่อความปลอดภัย — ผู้ที่มีสิทธิ์อ่านไฟล์ .bash_history จะเห็นคำสั่งย้อนหลังได้ทั้งหมด

เกร็ดที่มักถูกถามในงานจริงสาย Cloud Engineer

on-the-job notes เพิ่มทั้งหัวข้อ
  • Bastion host / Jump server: เครื่อง bastion มักถูกตั้ง HISTTIMEFORMAT และเก็บ log แยกไว้เพื่อ audit เพราะทุกคนต้องผ่านเครื่องนี้ก่อนเข้า production
  • ระวังตอน SSH หลุด: ถ้า session ถูกตัดกลางคันโดยไม่ได้ logout ปกติ (เช่นไฟดับ, network ขาด) คำสั่งใน session นั้นอาจไม่ถูก flush ลง .bash_history เพราะการเขียนไฟล์ปกติเกิดตอนปิด session — ถ้าอยากมั่นใจว่าบันทึกแน่นอนให้ใช้ history -a เป็นระยะ หรือใช้ script logging เช่น script command
  • Container / immutable infra: ใน container ที่ถูกทำลายทิ้งหลังใช้งาน (ephemeral) การพึ่งพา .bash_history ไม่มีประโยชน์สำหรับ audit ระยะยาว ควรส่ง log ไปที่ central logging (เช่น CloudTrail, Cloud Logging, ELK) แทน
  • ตั้งค่าแบบ organization-wide: ในทีมงานจริงมักบังคับ HISTTIMEFORMAT และ HISTCONTROL ผ่าน /etc/profile.d/*.sh เพื่อให้ทุกเครื่องในองค์กรมีมาตรฐาน log เดียวกัน ไม่ปล่อยให้ผู้ใช้แต่ละคนตั้งเองใน .bashrc

Q1 คำสั่งใดใช้แสดงเฉพาะ 5 คำสั่งล่าสุดที่เคยรัน?
เฉลยhistory 5
Q2 ถ้าต้องการรันคำสั่งลำดับที่ 42 ซ้ำทันที ต้องพิมพ์อะไร?
เฉลย!42
Q3 ตัวแปร HISTCONTROL ค่าใดที่ทำให้คำสั่งที่ขึ้นต้นด้วยช่องว่างไม่ถูกบันทึก?
เฉลยignorespace (หรือรวมอยู่ใน ignoreboth)
Q4 HISTSIZE กับ HISTFILESIZE ต่างกันอย่างไร?
เฉลยHISTSIZE จำกัดจำนวนคำสั่งที่เก็บใน RAM ระหว่าง session ปัจจุบัน ส่วน HISTFILESIZE จำกัดจำนวนคำสั่งที่เก็บอยู่ในไฟล์บนดิสก์ (~/.bash_history)
Q5 ต้องการล้างประวัติทั้งใน RAM และในไฟล์ทันที ต้องทำอย่างไร?
เฉลยใช้ history -c เพื่อล้างใน RAM ร่วมกับ > ~/.bash_history เพื่อเคลียร์ไฟล์ให้ว่างเปล่า ทำทั้งสองคำสั่งจึงจะครบทั้งสองที่
Q6 shopt -s histappend มีประโยชน์อย่างไรเมื่อเปิด terminal หลายหน้าต่างพร้อมกัน?
เฉลยทำให้แต่ละ session เขียนประวัติแบบต่อท้ายไฟล์ (append) แทนที่จะเขียนทับ ป้องกันไม่ให้ประวัติจาก terminal อื่นหายไปเมื่อ session ที่ปิดทีหลังบันทึกทับ
Q7 ต้องการดู timestamp ของแต่ละคำสั่งใน history ต้องตั้งตัวแปรใด?
เฉลยHISTTIMEFORMAT="%F %T "
Q8 ปิดการบันทึก history ถาวรสำหรับผู้ใช้ทุกคนในระบบ ต้องแก้ไขไฟล์ใด?
เฉลย/etc/profile โดยเพิ่มบรรทัด set +o history
Q9 ทำไม history -c เพียงอย่างเดียวจึงไม่เพียงพอต่อการซ่อนคำสั่งที่มีความลับ?
เฉลยเพราะล้างได้แค่ใน RAM ของ session ปัจจุบัน ส่วนไฟล์ .bash_history บนดิสก์ยังมีข้อมูลเดิมอยู่ (โดยเฉพาะคำสั่งที่ถูกบันทึกไปแล้วก่อนหน้า) ต้องเคลียร์ไฟล์แยกต่างหากด้วย
Q10 !$ กับ !^ ต่างกันอย่างไร?
เฉลย!$ ดึง argument ตัวสุดท้ายของคำสั่งก่อนหน้า ส่วน !^ ดึง argument ตัวแรกของคำสั่งก่อนหน้า

โจทย์ปฏิบัติ (ลงมือทำจริงในเทอร์มินัล)

hands-on
Drill 1

เปิด ~/.bashrc แล้วเพิ่ม HISTTIMEFORMAT="%F %T ", HISTCONTROL=ignoreboth, และ HISTIGNORE="ls:cd:pwd:clear" จากนั้น source ~/.bashrc แล้วตรวจสอบผลด้วย history

Drill 2

ลองรันคำสั่งใด ๆ แล้วเรียกกลับมาแก้ไขด้วย fc -e nano ตามด้วยเลขลำดับคำสั่งนั้น

Drill 3

จำลองสถานการณ์ "พิมพ์คำสั่งลับ" — ตั้ง HISTCONTROL=ignorespace แล้วพิมพ์คำสั่งโดยเว้นวรรคนำหน้า เช่น export API_KEY=xxxx แล้วตรวจสอบว่า history ไม่บันทึกคำสั่งนี้จริงหรือไม่

Drill 4

ทดลอง export HISTFILE=/dev/null ในหนึ่ง session แล้วปิด terminal ตรวจสอบว่า .bash_history ของ session นั้นไม่ถูกบันทึกเพิ่มเลย
