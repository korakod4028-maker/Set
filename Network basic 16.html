Application Layer Services

DNS · DHCP · HTTP(S) · SMTP/POP3/IMAP · FTP · SSH/Telnet · VoIP — สรุป แก้ข้อมูลที่คลาดเคลื่อน เพิ่มเนื้อหาระดับงานจริง พร้อมแบบฝึกหัด

สรุปเนื้อหา

กดหัวข้อเพื่อขยาย · กล่อง ส่วนเสริม = เนื้อหาที่เพิ่มเกินต้นฉบับ/แก้ไขให้ถูกต้อง

1. Client–Server และ Protocol คืออะไร

Client = ผู้ร้องขอ (Browser, PC) · Server = ผู้ให้บริการ (Web/DNS/Mail Server) — เป็น "บทบาท" ไม่ใช่ชนิดเครื่อง เครื่องเดียวเป็นได้ทั้งสองอย่าง

Protocol = ชุดกฎที่กำหนดรูปแบบข้อความ ลำดับการสื่อสาร ต้นทาง/ปลายทาง และการจัดการข้อผิดพลาด ทำงานได้ทุกชั้นของ TCP/IP (ไม่ได้อยู่แค่ Network Access Layer และไม่ได้ใช้เฉพาะเครือข่ายระยะไกล)

PDU / Encapsulation: Data (App) → Segment (TCP) / Datagram (UDP) → Packet (IP) → Frame (Ethernet) → Bits
2. DNS — แปลงชื่อเป็น IP (UDP/TCP 53)
พิมพ์ www.cisco.com→DNS Query→DNS Response (IP)→HTTP Request→HTTP Response→Browser render

DNS Request ≠ HTTP Request: DNS ขอ "ที่อยู่" ส่วน HTTP ขอ "หน้าเว็บ" · ถ้ามี DNS Cache ก็ข้ามการถามได้

ที่บ้าน: ISP ให้ DNS address แก่ Router → Router แจกต่อผ่าน DHCP (และมักทำหน้าที่ DNS Forwarder)

ส่วนเสริม: DNS Record ที่ต้องรู้ — A (name→IPv4), AAAA (IPv6), CNAME (alias), MX (mail server ของโดเมน), NS (name server), TXT (SPF/DKIM/verify), PTR (IP→name), SOA. ใช้ UDP เป็นหลัก แต่ใช้ TCP เมื่อคำตอบใหญ่เกิน, Zone Transfer, หรือ DNS over TLS (853). เครื่องมือ: nslookup, dig, host
# Windows / Linux
nslookup www.cisco.com
nslookup -type=MX gmail.com
dig +short A www.cisco.com
dig @8.8.8.8 www.cisco.com # ถามผ่าน DNS Server ที่เลือก
ipconfig /flushdns # Windows ล้าง cache
3. DHCP — แจก IP อัตโนมัติ (UDP 67 server / 68 client)

แจก IP, Subnet Mask, Default Gateway, DNS Server · ถ้าไม่มี DHCP ต้องตั้ง Static เอง

D iscover (broadcast)→O ffer→R equest→A cknowledge
ส่วนเสริม: IP ที่ได้มี Lease time (ต่ออายุที่ 50% ของ lease) · ถ้าไม่ได้ DHCP เครื่อง Windows จะได้ APIPA 169.254.x.x = สัญญาณว่า "DHCP Server ติดต่อไม่ได้" · DHCP Relay (ip helper-address) ส่ง Discover ข้ามเครือข่ายไปหา server กลาง · Server/Router ควรกัน Static IP ออกจาก Pool
ipconfig /all # ดู DHCP Server, Lease
ipconfig /release && ipconfig /renew
sudo dhclient -v eth0 # Linux
4. HTTP / HTTPS / HTML (TCP 80 / 443)

HTTP = โปรโตคอลรับส่งเว็บ · HTML = ภาษา Markup กำหนดโครงสร้างหน้าเว็บ (ไม่ใช่ Protocol — ตัวหลอกยอดนิยมในข้อสอบ) · HTTPS = HTTP + TLS (เข้ารหัส + ตรวจตัวตน server ด้วย certificate)

HTTP ทำงานบน TCP จึงต้อง 3-way handshake (SYN → SYN-ACK → ACK) และมี ACK → เกิด Traffic Overhead แลกกับความน่าเชื่อถือ

Methodหน้าที่Status codeความหมาย
GETขอข้อมูล200 / 301 / 302OK / Redirect
POSTส่งข้อมูล403 / 404Forbidden / Not Found
PUTสร้าง/แทนที่500 / 502 / 503Server error / Bad gateway / Unavailable
DELETEลบ401ต้อง Authenticate
ส่วนเสริม: HTTP/1.1 และ HTTP/2 ใช้ TCP แต่ HTTP/3 ใช้ QUIC บน UDP 443 · ห้ามใช้ HTTP ธรรมดากับข้อมูลสำคัญ
curl -I https://www.cisco.com # ดู header + status
curl -v http://example.com # ดู request/response ทั้งหมด
5. Email — SMTP / POP3 / IMAP4
Email Client—SMTP→Mail Server ผู้ส่ง—SMTP→Mail Server ผู้รับ—POP3/IMAP→Client ผู้รับ
Protocolหน้าที่Portแบบเข้ารหัส
SMTPส่ง25587 (submission, STARTTLS) / 465 (implicit TLS)
POP3ดาวน์โหลด (ค่าเริ่มต้นลบจาก server)110995
IMAP4เข้าถึง/ซิงก์ ต้นฉบับอยู่บน server143993
ส่วนเสริม: Client ส่งเมลควรใช้ 587 ส่วน 25 ใช้ server-to-server (ISP หลายแห่งบล็อก 25 ขาออก) · Mail server หา server ปลายทางจาก MX record · กันปลอมอีเมลด้วย SPF/DKIM/DMARC (เก็บใน TXT record)
ข้อสอบ: "ส่งและรับอีเมล เลือก 2" = SMTP + POP · "Client ดึงอีเมล เลือก 2" = POP + IMAP
6. FTP — ถ่ายโอนไฟล์ (TCP 21 control / 20 data)

2 การเชื่อมต่อ: Control (21) ส่งคำสั่ง · Data ส่งไฟล์ · Client เป็นฝ่ายเริ่ม Control เสมอ · ไฟล์ใหญ่ไม่ได้แปลว่าต้องมีมากกว่า 2 connection

โหมดใครเริ่ม Data Connectionพอร์ต
ActiveServer → ClientServer ใช้ 20 เป็นต้นทาง
PassiveClient → Serverพอร์ตสูงที่ server กำหนด (ไม่ใช่ 20) — Lab ของ Cisco เป็น Passive

คำสั่ง: put=upload · get=download · dir · rename · delete · cd · pwd · quit · Login สำเร็จ = 230

FTP ไม่เข้ารหัส (user/pass เป็น plaintext) → ใช้ SFTP (ทำงานบน SSH, port 22 — คนละโปรโตคอลกับ FTP) หรือ FTPS (FTP+TLS, 990)
7. SSH vs Telnet — Remote Access
TelnetSSH
PortTCP 23TCP 22
เข้ารหัสไม่มี (plaintext)มี
Authenticationมี (แต่ส่งรหัสผ่านโล่ง)มี (password / public key)
แก้ความเข้าใจ: ข้อ "ข้อดีของ SSH" คำตอบคือ การสื่อสารที่ปลอดภัย (encryption) — ไม่ใช่ "รองรับ authentication" เพราะ Telnet ก็ถามรหัสผ่านเช่นกัน
ส่วนเสริม: งานจริงใช้ SSH key แทนรหัสผ่าน · ปิด root login · SSH ทำ port forwarding/tunnel และ scp/sftp ได้ · Prompt Router> = User EXEC, Router# = Privileged EXEC

ssh-keygen -t ed25519
ssh-copy-id user@server

8. Text Messaging และ VoIP

Text messaging: ใช้ได้ทั้งมือถือ คอมพิวเตอร์ และเว็บ (Web-based / Standalone client) ส่งไฟล์ วิดีโอ เสียงได้ → "ใช้ได้เฉพาะสมาร์ตโฟน" = False

VoIP: เสียง Analog → Digital → Encapsulate ใน IP Packet → ปลายทางแปลงกลับ · โทรหาเบอร์ทั่วไปต้องผ่าน PSTN Gateway · Call Manager จัดการสาย ไม่จำเป็นต้องส่งเสียงทั้งหมด

ส่วนเสริม: VoIP ไวต่อ delay/jitter/packet loss → ใช้ UDP + RTP สำหรับเสียง, SIP (5060/5061) สำหรับสร้างสาย และตั้ง QoS ให้ voice มาก่อน
