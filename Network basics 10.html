ลองย่อ IPv6 เอง

1. ทำไมต้อง IPv6

IPv4 = 32 bits ≈ 4.3 พันล้าน address ไม่พอกับอุปกรณ์/IoT → เกิด address depletion. NAT ช่วยยืดอายุ แต่ไม่ได้เพิ่ม address จริง และทำให้ P2P/บางแอปยากขึ้น. IPv6 = 128 bits ≈ 3.4×1038 (340 undecillion).

ข้อสอบชอบหลอก: IPv6 ไม่ได้ “เร็วกว่า” โดยอัตโนมัติ. เหตุผลหลักคือ address หมด ไม่ใช่ความเร็ว/ความปลอดภัย.

2. โครงสร้าง address

200116 bit0db816 bit0000zero111116 bit0000zero0000zero0000zero020016 bit

1 hex digit = 4 bits · 1 hextet = 4 digits = 16 bits · 8 hextets = 32 digits = 128 bits. Hex ใช้ 0–9, A–F (ไม่มี G) และไม่แยกตัวพิมพ์เล็ก/ใหญ่.

3. กฎการย่อ (ทำตามลำดับ)

Rule 1: ตัด leading zeros ในแต่ละ hextet (เหลืออย่างน้อย 1 หลัก) — 0db8→db8, 0000→0, แต่ ab00 และ 1000 ห้ามแตะ.
Rule 2: ใช้ :: แทน hextet ที่เป็น 0 ติดกัน ครั้งเดียว · เลือกชุดที่ยาวที่สุด · ยาวเท่ากันเลือกชุดแรก.

2001:0db8:0000:0000:ab00:0000:0000:0000 → 2001:db8:0:0:ab00::

ทำไม :: ได้ครั้งเดียว? ถ้ามี 2 ที่ จะรู้ไม่ได้ว่าแต่ละที่แทนกี่ hextet.

4. IPv4/IPv6 Coexistence

วิธีทำอะไรจำ
Dual stackมี IPv4+IPv6 บน interface เดียวกัน“Native IPv6” ในข้อสอบ
Tunnelingห่อ IPv6 packet ใน IPv4 packetencapsulation
Translation (NAT64)แปลง IPv6-only ↔ IPv4-onlyต้องคู่กับ DNS64

เป้าหมายระยะยาว: native IPv6 end-to-end และลด tunnel/translation.

จุดที่ในเอกสารผิดหรือคลาดเคลื่อน

1. ลำดับ RIR หมด สลับกัน — ในไฟล์สรุป 10.0–10.1 ตารางวันที่ผิดชื่อ (LACNIC ≠ เม.ย. 2011) และไฟล์ Check Your Understanding เรียงชื่อผิดลำดับ. ลำดับตามที่ Cisco สอน: APNIC (เม.ย. 2011) → RIPE NCC (ก.ย. 2012) → LACNIC (มิ.ย. 2014) → ARIN (ก.ค. 2015) → AfriNIC (2020, ยังอยู่ช่วงทยอยแจกเหลือ). ข้อสอบ True = 4 ใน 5 ยังถูก. วันที่จริงแต่ละ RIR นิยามต่างกัน (เริ่ม soft landing vs หมดเกลี้ยง) ควรเช็กกับเว็บ RIR ถ้าจะอ้างในงานจริง.
2. “Native IPv6 = Dual stack” ถูกแค่ในบริบทข้อสอบ Cisco. ความจริง native IPv6 คือส่ง IPv6 ตรงโดยไม่ห่อ/แปล; dual stack คือโหมดที่ให้ native IPv6 อยู่ข้าง IPv4 ได้ ส่วน IPv6-only ก็ native เหมือนกัน.
3. ตารางเปรียบเทียบในไฟล์ 5 มีแถว “bits ต่อหลัก Hex” ของ IPv4 ที่ไม่สื่อความหมาย และช่องจำนวน address ว่าง. ใช้ตารางในแท็บสรุปแทน.
4. “ICMPv6 มีสิ่งที่ ICMPv4 ไม่มี” ควรพูดให้ชัด: ICMPv6 รวม Neighbor Discovery (แทน ARP) และ Router Advertisement สำหรับ SLAAC — ทำให้ ICMPv6 จำเป็นต่อการทำงาน ห้าม block ทิ้งทั้งหมดบน firewall.
5. :: แทน 1 hextet — Cisco ยอมให้ แต่ RFC 5952 (แนวปฏิบัติจริง) แนะนำ ไม่ใช้ :: กับศูนย์เพียงกลุ่มเดียว (เขียน :0:) และให้ใช้ตัวพิมพ์เล็กเพื่อให้ log/grep ตรงกัน.

โครงสร้างและการตั้งค่า

  • Prefix length เขียน /n เหมือน CIDR; subnet ทั่วไป = /64 (64 bit network + 64 bit interface ID). ลูกค้า/ไซต์มักได้ /48–/56.
  • การได้ address: SLAAC (Router Advertisement), DHCPv6, หรือ static.
  • Header ของ IPv6 คงที่ 40 bytes, ไม่มี header checksum, router ไม่ fragment (ส่งผ่าน Path MTU Discovery) → block ICMPv6 “Packet Too Big” แล้ว connection จะค้างแบบหาสาเหตุยาก.
  • NAT64 ใช้คู่กับ DNS64; มี 464XLAT สำหรับแอปที่ hardcode IPv4. Tunneling ในงานจริง: 6in4, GRE, (6to4/Teredo เลิกใช้แล้ว).
  • ถ้าไม่มี NAT ไม่ได้แปลว่าปลอดภัยน้อยลง — ความปลอดภัยมาจาก firewall/security group ไม่ใช่ NAT.

มุม Cloud Engineer

AWS VPC: เปิด IPv6 ได้โดยให้ VPC CIDR แบบ /56 (Amazon จัดสรรให้) และ subnet เป็น /64. Dual stack subnet ต้องเพิ่ม route ::/0 ไป Internet Gateway และเพิ่มกฎ IPv6 ใน security group/NACL แยกจากกฎ IPv4. Private subnet ที่ต้องออก internet แบบ IPv6 ใช้ Egress-only Internet Gateway (เทียบ NAT gateway แต่ไม่ต้องแปล).
เหตุผลเชิงต้นทุน: AWS คิดค่า public IPv4 ต่อชั่วโมงตั้งแต่ต้นปี 2024 ทำให้การใช้ IPv6 ลดต้นทุนได้จริง (เช็กราคาปัจจุบันในเอกสาร AWS ก่อนใช้งาน). Azure และ GCP ก็รองรับ dual stack VNet/VPC เช่นกัน แต่รายละเอียดต่างกัน.
Checklist เวลา debug:
  1. ip -6 addr / ip -6 route — มี GUA และ default route ไหม
  2. ping -6, curl -6, dig AAAA — AAAA record มีและ resolve ถูกไหม
  3. security group / NACL มีกฎ IPv6 ไหม (มักลืม)
  4. ICMPv6 ถูก block ไหม (ND, PMTUD)
  5. แอป bind แค่ 0.0.0.0 แทน :: หรือเปล่า
หัวข้อต่อไปที่ควรเรียนต่อ: subnetting IPv6, SLAAC/EUI-64, DHCPv6, DNS AAAA, security group แบบ dual stack.
