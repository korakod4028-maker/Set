💡 Alias คืออะไร
Alias (คำสั่งย่อ) คือการตั้งชื่อใหม่ให้แทนคำสั่งที่ยาวหรือมี option/parameter เยอะๆ เพื่อไม่ต้องพิมพ์ซ้ำๆ หลายร้อยครั้งต่อวัน — สะดวกและลดความผิดพลาดได้ดีกว่าการกดหาจาก history

Alias เป็นฟีเจอร์ของ Shell (เช่น bash, zsh) ไม่ใช่ของโปรแกรมที่เรียกใช้ — เวลาพิมพ์ชื่อ alias, shell จะแทนที่ด้วยคำสั่งเต็มก่อนรันจริง

Syntax — โครงสร้างคำสั่ง
⌨️ การสร้างและจัดการ Alias
alias lh='ls -alh' # สร้าง alias ชื่อ lh
alias # แสดง alias ทั้งหมดในเซสชันนี้
unalias lh # ลบ alias ชื่อ lh
alias name='cmd' โครงสร้างหลัก — ห้ามเว้นวรรครอบเครื่องหมาย = ไม่งั้น shell จะ error
alias พิมพ์เดี่ยวๆ เพื่อดูรายการ alias ทั้งหมดที่มีในเซสชันปัจจุบัน
alias lh ดูว่า alias ชื่อนี้ผูกกับคำสั่งอะไร (ระบุชื่อเดียว)
unalias lh ลบ alias ออกจากเซสชันปัจจุบัน
unalias -a ลบ alias ทั้งหมด ออกจากเซสชันในครั้งเดียว

⚠️ ข้อจำกัดสำคัญ: Alias ที่สร้างผ่าน Terminal โดยตรง จะอยู่ได้แค่เซสชันปัจจุบันเท่านั้น — พอปิด Terminal หรือเปิดเซสชันใหม่ ค่านี้จะหายไปทันที ต้องทำให้ถาวรตามวิธีในแท็บถัดไป

ตัวอย่างการใช้งานจริง
🧪 Alias ที่นิยมใช้บ่อย
llalias ll='ls -alh' — ดูไฟล์แบบละเอียดพร้อมไฟล์ซ่อน
..alias ..='cd ..' — ถอยกลับไปโฟลเดอร์แม่เร็วขึ้น
gsalias gs='git status' — คำสั่ง git ที่ใช้บ่อยที่สุด
updatealias update='sudo apt update && sudo apt upgrade -y'
👤 Alias ถาวรเฉพาะผู้ใช้ (Per-User Permanent)
มี 2 วิธีหลักในการทำให้ alias ใช้งานได้ตลอดไป สำหรับผู้ใช้คนนั้นๆ เท่านั้น
วิธีที่ 1
📝 เขียนลงไฟล์ ~/.bashrc
echo "alias lh='ls -alh'" >> ~/.bashrc # เพิ่มท้ายไฟล์
source ~/.bashrc # โหลดใช้ทันที ไม่ต้อง restart
1
เพิ่มบรรทัด alias ท้ายไฟล์ใช้ echo ... >> ~/.bashrc (สองขีด >> = append ต่อท้าย ไม่ใช่เขียนทับ)
2
สั่ง source เพื่อรีโหลดsource ~/.bashrc ให้ shell อ่านไฟล์ใหม่ทันที โดยไม่ต้องปิดเปิด terminal
วิธีที่ 2 (แนะนำ — เป็นระเบียบกว่า)
📁 เขียนลงไฟล์แยก ~/.bash_aliases
echo "alias lh1='ls -alh'" >> ~/.bash_aliases
source ~/.bashrc # ต้อง source .bashrc เหมือนเดิม
ไฟล์ .bashrc มาตรฐานส่วนใหญ่มักมีเงื่อนไขคอยดึงไฟล์นี้มาทำงานอัตโนมัติอยู่แล้ว:
if [ -f ~/.bash_aliases ]; then
  . ~/.bash_aliases
fi

✅ ข้อดีของการแยกไฟล์ .bash_aliases คือทำให้ .bashrc ไม่รก และเก็บ alias ทั้งหมดไว้ที่เดียว จัดการ/แบ็กอัพง่ายกว่า

❓ ทำไมต้อง source ทุกครั้ง?
คำสั่ง source (หรือสัญลักษณ์ .) คือการสั่งให้อ่านและรันไฟล์ตั้งค่าในเชลล์ปัจจุบันทันที

ถ้ารันสคริปต์ปกติแบบ ./script.sh โดยไม่ใช้ source สคริปต์จะถูกนำไปรันใน Sub-shell แยกต่างหาก — การเปลี่ยนแปลง (เช่น alias ใหม่, ตัวแปร environment) จะไม่ส่งผลกลับมาที่ shell ปัจจุบันที่เราใช้งานอยู่
🌐 Alias ถาวรสำหรับผู้ใช้ทุกคน (System-Wide)
หากต้องการให้ผู้ใช้ทุกคน (All Users) ในเครื่องใช้ alias นี้ร่วมกันได้ ต้องตั้งค่าที่ระดับระบบ
📂 ไดเรกทอรี /etc/profile.d/
1
ผู้ใช้เปิดเซสชันใหม่ (login)ระบบจะรันไฟล์หลัก /etc/profile โดยอัตโนมัติ
2
/etc/profile เรียก /etc/profile.d/*.shไฟล์ .sh ทุกไฟล์ในโฟลเดอร์นี้จะถูกรันตามลำดับตัวอักษร (Alphabetical Order)
3
Alias พร้อมใช้งานทุก userผู้ใช้ทุกคนที่ล็อกอินเข้าเครื่องนี้จะเห็น alias เดียวกัน
echo "alias lh2='ls -alh'" >> /etc/profile.d/99-aliases.sh
✅ Best Practice
99-aliases.sh ใส่ ตัวเลขนำหน้าชื่อไฟล์เพื่อคุมลำดับการรัน เช่น 99- เพื่อให้รันหลังสุด (เพราะรันตามลำดับตัวอักษร ตัวเลขมากกว่า = รันทีหลัง)

⚠️ ไม่ควรแก้ไฟล์ /etc/profile โดยตรง — เพราะเป็นไฟล์ระบบหลักที่อาจถูก package manager เขียนทับตอนอัปเดตระบบ ควรสร้างไฟล์ใหม่แยกไว้ใน /etc/profile.d/ เสมอ

🔑 สิทธิ์ที่ต้องใช้
การเขียนไฟล์ใน /etc/profile.d/ ต้องใช้สิทธิ์ root (เช่น sudo) เพราะเป็นการตั้งค่าระดับระบบที่กระทบผู้ใช้ทุกคน — ต่างจาก ~/.bashrc ที่แก้ไขได้เองโดยไม่ต้องใช้ sudo
เนื้อหาเสริมที่ควรรู้ (ไม่มีในเอกสารต้นฉบับ แต่ออกข้อสอบบ่อย)
🥇 ลำดับความสำคัญเมื่อพิมพ์คำสั่ง (Command Resolution Order)
เมื่อพิมพ์ชื่อคำสั่งใดๆ bash จะค้นหาตามลำดับนี้:
1
Aliasถ้าชื่อตรงกับ alias ที่ตั้งไว้ จะถูกแทนที่ก่อนเป็นอันดับแรก
2
Functionฟังก์ชันที่ประกาศไว้ใน shell
3
Builtinคำสั่งในตัวของ shell เอง เช่น cd, echo
4
PATH (External Command)โปรแกรมจริงในระบบ เช่น /bin/ls

ใช้คำสั่ง type lh เพื่อเช็กว่าชื่อที่พิมพ์คือ alias, function, builtin หรือ external command — มีประโยชน์มากตอน debug ว่าทำไมคำสั่งทำงานไม่ตรงกับที่คาดไว้

🚫 การข้าม (Bypass) Alias ชั่วคราว
บางครั้งต้องการรันคำสั่งจริง โดยไม่ให้ alias มาแทรก ทำได้ 3 วิธี:
\ls # ใส่ backslash นำหน้า → ข้าม alias
'ls' # ครอบด้วย single quote → ข้าม alias
command ls # ใช้ builtin "command" → บังคับใช้คำสั่งจริง
💬 Single Quote กับ Double Quote ใน Alias
รูปแบบพฤติกรรม
'single'ตัวแปร ($VAR) จะไม่ถูกแทนค่าตอนสร้าง alias — ค่าจะถูกอ่านใหม่ทุกครั้งที่เรียกใช้ alias (แนะนำใช้แบบนี้เป็นหลัก)
"double"ตัวแปรจะถูกแทนค่าทันทีตอนสร้าง alias และค่านั้นจะถูก "จำตาย" ไว้ ไม่อัปเดตตามค่าจริงภายหลัง

⚠️ กับดักข้อสอบ: alias show="echo $HOME" จะจำค่า HOME ตอนนั้นตายตัว แต่ alias show='echo $HOME' จะอ่านค่า HOME ใหม่ทุกครั้งที่เรียก

⚖️ Alias vs Function
Alias รับพารามิเตอร์ไม่ได้โดยตรง และรันได้แค่คำสั่งเดียวแบบง่ายๆ ถ้าต้องใช้ logic ซับซ้อนหรือรับ argument ต้องใช้ Shell Function แทน
🖥️ Alias กับ Script
Alias ทำงานเฉพาะใน Interactive Shell เท่านั้น — ถ้าเขียนใน Shell Script ทั่วไปจะไม่ทำงาน เว้นแต่เปิด shopt -s expand_aliases ก่อน
📋 Cheat Sheet ฉบับสมบูรณ์
alias name='cmd'สร้าง alias ชั่วคราว (หายเมื่อปิด session)
aliasแสดง alias ทั้งหมดในเซสชันปัจจุบัน
unalias nameลบ alias หนึ่งตัว
unalias -aลบ alias ทั้งหมดในเซสชัน
type nameเช็กว่าชื่อนี้คือ alias / function / builtin / command
\nameข้าม alias แล้วรันคำสั่งจริง
command nameบังคับรันคำสั่งจริง ไม่ผ่าน alias/function
~/.bashrcไฟล์ตั้งค่าถาวรของ user คนเดียว
~/.bash_aliasesไฟล์แยกเก็บ alias โดยเฉพาะ (ถูกดึงเข้า .bashrc)
/etc/profile.d/*.shไฟล์ตั้งค่าถาวรสำหรับ ทุก user ในเครื่อง (ต้อง sudo)
source ~/.bashrcโหลดไฟล์ตั้งค่าใหม่ทันที ไม่ต้อง restart terminal
💡 Engineer Tips — ใช้งานจริง
→
ใช้ .bash_aliases แยกจาก .bashrc เสมอในสายงาน — ทำให้ sync/backup dotfiles ผ่าน git ได้เป็นระเบียบ
→
ตั้งชื่อไฟล์ใน /etc/profile.d/ ด้วยเลขนำหน้าเสมอ (10-, 99-) เพื่อคุมลำดับการโหลดให้ชัดเจน
→
ถ้า alias ไม่ทำงานหลังแก้ไฟล์ อย่าลืม source ก่อนเสมอ — เป็นจุดพลาดที่พบบ่อยที่สุด
→
ใช้ single quote '...' เป็นค่าเริ่มต้นเสมอเวลาสร้าง alias ที่มีตัวแปร เพื่อป้องกันค่าค้าง
→
ถ้าต้อง deploy alias ให้เครื่อง server หลายเครื่องพร้อมกัน ให้เขียนเป็นไฟล์ /etc/profile.d/ แล้วดันผ่าน config management (Ansible/Terraform) แทนการรันคำสั่งทีละเครื่อง
