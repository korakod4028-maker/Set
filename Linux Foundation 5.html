แนวคิดพื้นฐาน — Pipe คืออะไร
🔀 Pipe — เครื่องหมาย |
Cmd1 | Cmd2 Pipe — นำ stdout (ผลลัพธ์) ของคำสั่งซ้าย ไปเป็น stdin (ข้อมูลนำเข้า) ของคำสั่งขวาโดยตรง
ไม่ผ่านการสร้างไฟล์ชั่วคราวใดๆ
Cmd1 | Cmd2 | Cmd3 ต่อ pipe กี่ทอดก็ได้ — ผลลัพธ์จะไหลจากซ้ายไปขวาเป็นทอดๆ เหมือนสายพาน

🏭 เปรียบเทียบ: Pipe เหมือน สายพานโรงงาน — วัตถุดิบ (output) จากสถานีที่ 1 ถูกส่งต่อไปแปรรูปที่สถานีที่ 2 ทันที โดยไม่ต้องพักไว้ที่ไหนก่อน

⚠️ อย่าสับสน: | (pipe เดี่ยว) ใช้ส่งข้อมูล แต่ || (สองอัน) คือ logical OR ในการเขียน shell script — ใช้คนละความหมายกันโดยสิ้นเชิง

แนวคิดพื้นฐาน — Redirection คืออะไร
📤 Redirection — เปลี่ยนทิศทางข้อมูลเข้า/ออก
Redirection คือการเปลี่ยนปลายทางของข้อมูล จากที่ปกติจะวิ่งเข้า/ออกหน้าจอ (terminal) ให้วิ่งเข้า/ออกไฟล์แทน
Operatorชื่อเรียกหน้าที่
>Overwriteเขียนผลลัพธ์ลงไฟล์ — ถ้ามีไฟล์เดิมอยู่แล้ว จะลบทิ้งแล้วเขียนใหม่ทั้งหมด
>>Appendเขียนผลลัพธ์ลงไฟล์ — ต่อท้ายเนื้อหาเดิม ไม่ลบของเก่า
<Input Redirectดึงเนื้อหาจากไฟล์ ป้อนเข้าไปเป็น stdin ของคำสั่ง
<<Heredocป้อนข้อความหลายบรรทัดจากใน terminal เองจนกว่าจะเจอคำปิด (delimiter)

✍️ จำง่ายๆ: > ตัวเดียว = ฉีกกระดาษเก่าทิ้งแล้วเขียนใหม่  ·  >> สองตัว = จดต่อท้ายบรรทัดล่างสุดของกระดาษเดิม

⌨️ ตัวอย่างการใช้งาน Redirection
ls -al > list.txtบันทึกผลลัพธ์ของ ls -al ลงไฟล์ list.txt (สร้างใหม่/เขียนทับ)
echo "Done" >> list.txtเพิ่มข้อความ Done ต่อท้ายไฟล์ list.txt โดยไม่ลบของเดิม
wc -l < numbers.txtป้อนเนื้อหาไฟล์ numbers.txt เข้าคำสั่ง wc -l โดยตรง ผลลัพธ์จะเป็นตัวเลขล้วน ไม่มีชื่อไฟล์ติดมา
sort < names.txt > sorted.txtอ่านจากไฟล์หนึ่ง เรียงลำดับ แล้วเขียนผลลัพธ์ลงอีกไฟล์หนึ่ง — ใช้ < และ > พร้อมกันได้
🌊 3 ช่องทางข้อมูลมาตรฐาน (Standard Streams)
0 · stdin
Standard Input ช่องทางรับข้อมูลเข้าคำสั่ง — ปกติคือคีย์บอร์ด แต่เปลี่ยนได้ด้วย < หรือ |
1 · stdout
Standard Output ช่องทางผลลัพธ์ปกติของคำสั่ง — ปกติออกหน้าจอ เปลี่ยนได้ด้วย >, >> หรือ |
2 · stderr
Standard Error ช่องทางข้อความ error — แยกจาก stdout เพื่อไม่ให้ error ปนกับผลลัพธ์ปกติ เปลี่ยนได้ด้วย 2>

💡 ทุกช่องทางมีเลขประจำตัว (file descriptor): 0 = stdin, 1 = stdout, 2 = stderr — เวลาเขียน > เฉยๆ ระบบจะเข้าใจว่าหมายถึง 1> โดยอัตโนมัติ

🎯 การ Redirect เฉพาะ stderr
cmd 2> error.logส่งเฉพาะ errorไปเก็บไว้ในไฟล์ error.log ส่วนผลลัพธ์ปกติยังขึ้นหน้าจอ
cmd 2>/dev/nullทิ้ง error ทั้งหมด — /dev/null คือ "ถังขยะ" ของระบบ Linux ใส่อะไรเข้าไปก็หายไปเลย
cmd > out.log 2>&1รวม stdout และ stderr ไปไฟล์เดียวกัน — 2>&1 แปลว่า "ให้ stream 2 ไปทางเดียวกับ stream 1"
cmd &> all.logรูปแบบย่อของ > file 2>&1 ใน bash — รวมทั้ง stdout และ stderr ในคำสั่งเดียว

⚠️ กับดักข้อสอบ: ลำดับสำคัญมาก! cmd > file 2>&1 ถูกต้อง (รวมทั้งคู่ไปที่ file) แต่ cmd 2>&1 > file จะไม่ได้ผลแบบเดียวกัน เพราะตอนสั่ง 2>&1 stdout ยังชี้ไปที่หน้าจออยู่

คำสั่งยอดฮิตที่ใช้คู่กับ Pipe
🧰 Toolbox พื้นฐานสำหรับต่อ Pipe
sortเรียงลำดับข้อมูลตามตัวอักษร (A→Z) เป็นค่า default
sort -rReverse — เรียงย้อนกลับ (Z→A)
sort -nNumeric — เรียงแบบตัวเลขจริง (ไม่ใช่เรียงแบบ string ที่ "10" จะมาก่อน "9")
uniqลบบรรทัดที่ซ้ำติดกันออก — ต้อง sort ก่อนเสมอ ไม่งั้นจะลบซ้ำไม่หมด
uniq -cนับจำนวนที่แต่ละรายการซ้ำกัน แสดงเป็นตัวเลขนำหน้า
wc -l / -w / -cนับบรรทัด / คำ / ตัวอักษร (byte) ตามลำดับ
grep 'pattern'กรองเฉพาะบรรทัดที่ตรงกับ pattern ที่ระบุ
grep -c 'pattern'นับจำนวนบรรทัดที่ match แทนที่จะแสดงบรรทัดนั้นๆ
head -n5 / tail -n5แสดงเฉพาะ 5 บรรทัดบนสุด / ล่างสุด
tee file.txtเขียนผลลัพธ์ลงไฟล์ และ ส่งต่อไปยัง pipe ถัดไปด้วยพร้อมกัน (ไม่ใช่เลือกอย่างใดอย่างหนึ่งแบบ >)
xargs cmdแปลงข้อมูลจาก stdin ให้กลายเป็น argument ของคำสั่งถัดไป — ใช้เมื่อคำสั่งปลายทางไม่รับ stdin โดยตรง

⚠️ กับดักข้อสอบยอดฮิต: uniq ทำงานกับบรรทัดที่ซ้ำติดกันเท่านั้น ถ้าข้อมูลไม่เรียงก่อน (sort) ผลลัพธ์จะยังมีของซ้ำหลงเหลืออยู่ — สูตรที่ถูกต้องเสมอคือ sort | uniq

ตัวอย่างการต่อคำสั่งใช้งานจริง
💡 Real-World Pipeline Patterns
cat file.txt | sort | uniq | wc -lนับจำนวนคำที่ไม่ซ้ำกันในไฟล์ — sort ก่อน → ลบซ้ำ → นับบรรทัด
ls -al | grep '.txt'แสดงเฉพาะไฟล์ที่มีคำว่า .txt อยู่ในผลลัพธ์ของ ls -al
ps aux | grep nginxค้นหา process ที่ชื่อมีคำว่า nginx อยู่ — ใช้บ่อยมากตอน debug service
cat access.log | grep 404 | wc -lนับจำนวนบรรทัด log ที่มีรหัส 404 (Not Found) เกิดขึ้นทั้งหมด
du -sh * | sort -rh | head -10หา 10 ไฟล์/โฟลเดอร์ที่ใช้พื้นที่มากที่สุด ในไดเรกทอรีปัจจุบัน (-h ใน sort ใช้เรียง human-readable size เช่น 1K, 1M, 1G ได้ถูกต้อง)
cat file.txt | tee backup.txt | wc -lสำรองข้อมูลลง backup.txt พร้อมกับนับบรรทัดไปด้วยในคำสั่งเดียว
history | tail -20ดูคำสั่ง 20 รายการล่าสุดที่เคยพิมพ์ใน terminal
find . -name "*.log" | xargs rmค้นหาไฟล์ .log ทั้งหมด แล้วส่งชื่อไฟล์เหล่านั้นเป็น argument ให้ rm ลบทีเดียว
📋 Cheat Sheet ฉบับสมบูรณ์
|Pipe — ส่ง stdout ของคำสั่งซ้ายเข้า stdin ของคำสั่งขวา
>Overwrite — เขียนผลลัพธ์ลงไฟล์ ทับของเดิมทั้งหมด
>>Append — เขียนผลลัพธ์ต่อท้ายไฟล์ ไม่ลบของเดิม
<Input redirect — ป้อนเนื้อหาไฟล์เข้าเป็น stdin
<<Heredoc — ป้อนข้อความหลายบรรทัดจนกว่าจะเจอ delimiter
2>Redirect เฉพาะ stderr ไปไฟล์ที่ระบุ
2>/dev/nullทิ้ง error ทั้งหมดไม่ให้แสดงผล
> file 2>&1รวม stdout + stderr ไปไฟล์เดียวกัน (ต้องเรียงลำดับแบบนี้)
&>รูปแบบย่อของ > file 2>&1 ใน bash
sort | uniq | wc -lสูตรมาตรฐาน: เรียง → ลบซ้ำ → นับจำนวนไม่ซ้ำ
uniq -cนับจำนวนที่แต่ละรายการซ้ำกัน
grep 'x' / grep -c 'x'กรองบรรทัดที่ match / นับจำนวนบรรทัดที่ match
tee fileเขียนไฟล์ พร้อมส่งต่อ pipe ถัดไปในคำสั่งเดียว
xargsแปลง stdin ให้เป็น argument ของคำสั่งถัดไป
wc -l < fileนับบรรทัด ได้ผลลัพธ์เป็นตัวเลขล้วน ไม่มีชื่อไฟล์ติดมา
💡 Engineer Tips — ใช้งานจริง
→
ก่อนใช้ uniq ทุกครั้ง เช็กก่อนว่า sort มาก่อนหรือยัง — เป็นบั๊กที่พบบ่อยที่สุดในการเขียน pipeline
→
ใช้ 2>/dev/null เวลา run สคริปต์ที่รู้อยู่แล้วว่าจะมี error บางส่วนที่ไม่สำคัญ เพื่อให้ log สะอาด อ่านง่าย
→
ใช้ tee แทน > เมื่อยังอยากเห็นผลลัพธ์บนหน้าจอพร้อมกับบันทึกไฟล์ — > อย่างเดียวจะไม่โชว์อะไรบนหน้าจอเลย
→
จำสูตร "count → sort → uniq → wc" ไว้ให้ขึ้นใจ เป็น pattern ที่ออกข้อสอบและใช้งานจริงบ่อยที่สุด
→
ตรวจสอบ error log ของ production ด้วย tail -f app.log | grep ERROR เพื่อดู error แบบ real-time
→
เมื่อคำสั่งไม่รับ stdin โดยตรง (เช่น rm, mkdir) ให้ต่อด้วย xargs เสมอเพื่อแปลง stdin เป็น argument
