Network basics 13

MAC Address · IP Address · Broadcast · ARP — สรุปสำหรับเตรียมเป็น Cloud Engineer รวมจากบท 13.0–13.3 พร้อมจุดที่แก้และเพิ่ม

4 หลักการที่ต้องตอบได้ทันที 1) Same network → Dst MAC = MAC ปลายทาง   2) Remote network → Dst MAC ของ Frame แรก = MAC ของ Default Gateway   3) IPv4 ใช้ ARP / IPv6 ใช้ ND หา MAC   4) Router เปลี่ยน MAC ทุก Link แต่ IP โดยทั่วไปคงเดิม

1. จำลองการส่งข้อมูล: อะไรเปลี่ยน อะไรไม่เปลี่ยน

กด “ถัดไป” เพื่อเดินตาม Link ช่องที่ กระพริบพร้อมกรอบ คือค่าที่เปลี่ยนจากขั้นก่อนหน้า

MAC บอกว่า Frame รอบนี้ (Link นี้) ส่งให้ใคร   IP บอกว่า Packet ต้องไปหาใครในที่สุด

Router ทำอะไรเมื่อรับ Frame

  1. รับ Frame → ถอด Header/Trailer Layer 2 (de-encapsulate)
  2. ดู Destination IP
  3. ค้น Routing Table หา Next-hop และ Outgoing Interface
  4. ห่อ Packet ด้วย Frame ใหม่ (Src MAC = Interface ขาออก, Dst MAC = Next-hop หรือปลายทางสุดท้าย)
  5. ส่งออก (ถ้ายังไม่รู้ MAC ของ Next-hop จะ ARP/ND บน Link ขาออก)

เครื่องมือเช็กว่า Same หรือ Remote network

Host ทำ AND ระหว่าง IP กับ Subnet Mask ถ้า Network ID ตรงกัน = Same network ไม่ตรง = ส่งให้ Default Gateway (ซึ่งต้องอยู่ใน Subnet เดียวกับ Host)

3. Broadcast, Switch และ Broadcast Domain

  • Broadcast MAC = FF:FF:FF:FF:FF:FF = FFFF.FFFF.FFFF (Cisco) = 48 bits เป็น 1 ทั้งหมด (F หนึ่งตัว = 1111)
  • NIC รับ Frame เมื่อ Dst MAC เป็น MAC ตัวเอง, Broadcast หรือ Multicast ที่ตัวเองเข้าร่วม ถ้าเป็น MAC คนอื่นจะไม่รับ
  • Switch รับ Broadcast → Flood ออกทุก Port ใน VLAN เดียวกัน ยกเว้นพอร์ตขาเข้า
  • Router ไม่ Forward Ethernet Broadcast ข้าม Network → Router (และ VLAN) แบ่ง Broadcast Domain
  • Host มากเกินใน Domain เดียว = Broadcast traffic สูง ประสิทธิภาพตก → แบ่ง Subnet/VLAN

Switch เรียนรู้ MAC อย่างไร (เพิ่มเติม)

  • Learn: ดู Source MAC ของ Frame ที่เข้ามา แล้วจดคู่ MAC ↔ Port ใน MAC Address Table
  • Forward: ดู Dst MAC ถ้ารู้ Port → ส่งเฉพาะพอร์ตนั้น (Unicast)
  • Flood: ถ้า Dst เป็น Broadcast หรือ Unicast ที่ยังไม่รู้จัก (unknown unicast) → ส่งออกทุกพอร์ตยกเว้นขาเข้า

4. ARP — หา MAC จาก IPv4

ใช้เมื่อรู้ IPv4 ปลายทาง (ใน Local network) แต่ยังไม่รู้ MAC ขั้นตอน: ตรวจ ARP Table → ส่ง Request (Broadcast) → เจ้าของ IP ตอบ Reply → เก็บลง ARP Table

ARP RequestARP Reply
หน้าที่ถาม “ใครมี IP นี้”ตอบ “IP นี้ฉันเอง MAC คือ …”
Dst MACFFFF.FFFF.FFFFMAC ของผู้ถาม (Unicast)
ผู้ส่งเครื่องที่ต้องการ MACเครื่องที่ IP ตรงเท่านั้น (เครื่องอื่นเงียบ)
จุดที่สับสนบ่อยถ้าปลายทางอยู่คนละ Network Host จะ ไม่ ARP หา MAC ของ Server แต่ ARP หา MAC ของ Default Gateway ส่วน Router จะ ARP หา Next-hop/ปลายทางบน Link ขาออกของตัวเอง

ARP ที่ Engineer ต้องรู้เพิ่ม

  • ARP Table/Cache มีอายุ (ต่างกันตาม OS/อุปกรณ์) หมดอายุแล้วต้อง ARP ใหม่
  • Gratuitous ARP: เครื่องประกาศ IP↔MAC ของตัวเองโดยไม่มีใครถาม ใช้ตรวจ IP ซ้ำและอัปเดต Cache เมื่อ Failover (เช่น VRRP/HSRP, floating IP)
  • Proxy ARP: Router ตอบ ARP แทนเครื่องปลายทางที่อยู่ Network อื่น
  • ARP Spoofing: ARP ไม่มีการยืนยันตัวตน ผู้โจมตีตอบ Reply ปลอมเพื่อดักข้อมูล (Man-in-the-Middle) ป้องกันด้วย Dynamic ARP Inspection (DAI) บน Switch
  • EtherType ของ ARP = 0x0806, ของ IPv4 = 0x0800, ของ IPv6 = 0x86DD

Troubleshooting ตามลำดับ Layer

  1. เช็ก IP / Mask / Gateway ถูกต้อง และ Gateway อยู่ Subnet เดียวกับเครื่อง
  2. Ping Gateway ไม่ได้ → ดู ARP Table: ถ้า Gateway ไม่มี MAC (หรือ incomplete) ปัญหาอยู่ที่ L1/L2 เช่น สาย, พอร์ต, VLAN, Gateway ล่ม
  3. Ping Gateway ได้แต่ปลายทางนอก Subnet ไม่ได้ → ปัญหา L3: Route, ACL/Firewall, NAT
  4. Ping IP ได้แต่ชื่อไม่ได้ → DNS
  5. MAC ของ Gateway เปลี่ยนเอง หรือหลาย IP ใช้ MAC เดียวกัน → สงสัย ARP Spoofing หรือ IP ซ้ำ

เชื่อมกับ Cloud (AWS / Azure / GCP)

  • VPC/VNet เป็นเครือข่ายเสมือนที่ SDN จัดการ ไม่มี L2 Broadcast แบบ LAN จริง (Hypervisor ตอบ ARP/ND ให้) แต่ OS ในเครื่องยังเห็น ARP, Gateway และ MAC ตามหลักเดียวกัน ออกแบบระบบให้พึ่ง L3 Routing ไม่พึ่ง Broadcast
  • ตัวอย่าง AWS: Subnet 10.0.1.0/24 → Gateway ของ Instance คือ VPC Router ที่ 10.0.1.1 (Subnet คนละก้อนต้องผ่าน Route Table เสมอ)
  • MAC ผูกกับ Network Interface เสมือน (เช่น ENI) ย้าย/สร้างใหม่ MAC อาจเปลี่ยน อย่าใช้ MAC เป็นตัวระบุเครื่องถาวร
  • Security Group/NACL/Route Table ทำงานที่ L3–L4 ไม่ดู MAC
  • NAT Gateway เปลี่ยน Source IP — เป็นข้อยกเว้นของกฎ “IP ไม่เปลี่ยน”
  • Overlay (เช่น VXLAN) ห่อ Ethernet Frame ไว้ใน UDP Packet เพื่อขยาย L2 ข้ามเครือข่าย L3 — พื้นฐานของ Virtual Network ฝั่ง Cloud

7. จุดที่แก้ / เพิ่มจากเอกสารต้นฉบับ

รูปแบบเขียน MAC ไม่ควรปนกันบางจุดเขียน 000C:85CC:1DA7 รูปแบบ Cisco คือ 000C.85CC.1DA7 (จุด) ส่วน Linux/Wireshark ใช้ 00:0c:85:cc:1d:a7 และ Windows ใช้ 00-0C-85-CC-1D-A7
“Flood ทุก Port” ต้องจำกัดที่ VLANSwitch Flood เฉพาะพอร์ตใน VLAN เดียวกัน ยกเว้นพอร์ตขาเข้า
เอกสารขาดเรื่อง MAC Address TableSwitch เรียนรู้จาก Source MAC และ Flood เมื่อ Dst เป็น unknown unicast (ดูหัวข้อ 3)
NIC ไม่ได้รับแค่ “MAC ตัวเอง + Broadcast”ยังรับ Multicast ที่เข้าร่วมด้วย ตัวเลือก 01-00-5E-… ในข้อสอบคือ MAC ของ IPv4 Multicast ส่วน IPv6 ใช้ 33:33:…
“ND ใช้ Multicast” ให้เจาะจงNS ส่งไป Solicited-node Multicast ส่วน NA ตอบเป็น Unicast ND ไม่ได้แค่แทน ARP แต่ทำ RS/RA และ DAD ด้วย
“Router ไม่ Forward Broadcast” มีรายละเอียดRouter รับและประมวลผล ARP Request ที่ถามหา IP ของตัวเองได้ แต่ไม่ส่งต่อข้าม Interface (บริการอย่าง DHCP Relay คือ Router สร้างข้อความใหม่ ไม่ได้ส่ง Broadcast เดิมต่อ)
“MAC คงเดิมตลอด” ไม่เสมอไปปลอมได้ มือถือสมัยใหม่ใช้ MAC สุ่มตาม Wi-Fi และ NIC เสมือนบน Cloud เปลี่ยนได้
ข้อสอบ Packet Tracer (เช่น ข้อ 10)คำตอบอย่าง 0001.43EA.3E03 ขึ้นกับ Topology ในไฟล์ อย่าท่องค่า ให้ท่องวิธีคิด: Frame ออกจาก Interface ไหน → Source MAC คือ MAC ของ Interface นั้น
